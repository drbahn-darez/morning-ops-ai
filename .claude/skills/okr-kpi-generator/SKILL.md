# OKR/KPI 문서 생성 스킬

## 이 스킬이 하는 일

스타트업 경영진이 분기 또는 연간 단위로 필요한 OKR/KPI 문서를 빠르고 체계적으로 만들 수 있도록 돕는다. 사용자의 사업 맥락을 파악한 뒤, 업계 표준에 맞는 구조화된 문서를 생성한다.

## 사용자 인터뷰 (정보 수집)

문서를 생성하기 전에, 아래 정보를 사용자에게 확인한다. 이미 대화에서 파악된 정보는 다시 묻지 않는다.

### 필수 정보
1. **문서 유형**: OKR 설정 / KPI 대시보드 / 분기 리뷰 / 연간 계획 중 무엇이 필요한지
2. **기간**: 어떤 분기 또는 연도를 대상으로 하는지 (예: 2026 Q2, 2026 연간)
3. **사업 맥락**: 회사가 하는 일, 현재 단계 (Pre-seed ~ Series C+), 주요 제품/서비스
4. **핵심 목표 또는 방향성**: 이번 기간에 가장 중요한 것 (성장? 수익화? PMF? 채용?)

### 선택 정보 (있으면 더 좋은 문서가 나옴)
- 팀 구성 및 부서 (부서별 OKR 정렬이 필요한 경우)
- 현재 주요 지표 수치 (MAU, MRR, Churn 등)
- 이전 분기 OKR 결과 (있으면 연속성 있는 목표 설정 가능)
- 투자자/보드 공유 여부 (톤과 포맷에 영향)
- 출력 형식 선호 (마크다운이 기본, .docx나 .xlsx도 가능)

정보가 부족하면 합리적인 가정을 하되, 가정한 부분은 명시한다.

## 문서 유형별 생성 가이드

### 1. OKR 설정 문서

회사/팀의 분기 또는 연간 OKR을 설정하는 문서다.

**구조:**
```
# [회사명] OKR — [기간]

## 회사 미션 & 이번 기간 전략 방향
짧은 맥락 요약 (2-3문장)

## Company-Level OKR

### Objective 1: [동사로 시작하는 명확한 목표]
왜 이 목표가 중요한지 1-2문장으로 설명

- KR 1.1: [측정 가능한 결과] (현재: X → 목표: Y)
- KR 1.2: [측정 가능한 결과] (현재: X → 목표: Y)
- KR 1.3: [측정 가능한 결과] (현재: X → 목표: Y)

### Objective 2: ...
(동일 구조 반복)

## 부서별 OKR (해당 시)
각 부서의 OKR이 회사 OKR과 어떻게 연결되는지 명시

### [부서명]
#### Objective: ...
- KR 1: ...
(상위 Company OKR과의 연결: Objective X → KR X.X)

## KPI 트래킹 요약
핵심 지표와 목표치를 한눈에 볼 수 있는 표

| 지표 | 현재값 | 목표값 | 담당 | 측정 주기 |
|------|--------|--------|------|-----------|

## 실행 계획 & 마일스톤
월별 또는 주요 마일스톤 타임라인

## 리스크 & 의존성
목표 달성을 방해할 수 있는 요소와 대응 방안
```

**좋은 OKR 작성 원칙:**
- Objective는 영감을 주되 구체적이어야 한다. "성장하자"가 아니라 "핵심 시장에서 카테고리 리더로 자리잡는다" 같은 식.
- Key Result는 반드시 측정 가능해야 한다. "개선한다"가 아니라 "NPS 40에서 55로 올린다" 같은 식.
- 회사 OKR은 3-5개, 각 Objective당 KR은 2-4개가 적당하다. 너무 많으면 집중력이 흐려진다.
- 70% 달성이 기대되는 수준으로 목표를 잡는 것이 일반적이다 (stretch goal).
- KR에는 가능한 한 현재값(baseline)과 목표값(target)을 함께 적는다.

### 2. KPI 대시보드 문서

핵심 지표를 정의하고 추적하기 위한 문서다.

**구조:**
```
# [회사명] KPI 대시보드 — [기간]

## North Star Metric
가장 중요한 하나의 지표와 그 이유

## 카테고리별 KPI

### Growth (성장)
| KPI | 정의 | 현재값 | 목표값 | 추이 | 담당자 |
|-----|------|--------|--------|------|--------|

### Revenue (매출)
(동일 구조)

### Engagement (활성도)
(동일 구조)

### Efficiency (효율)
(동일 구조)

## 지표 간 관계도
어떤 지표가 어떤 지표에 영향을 미치는지 설명

## 알림 기준 (Thresholds)
주의/경고가 필요한 수치 기준
```

**KPI 선정 원칙:**
- 스타트업 단계에 맞는 지표를 선택한다. Pre-PMF면 retention과 engagement가 핵심, Post-PMF면 growth와 unit economics가 핵심.
- 허영 지표(vanity metrics)를 피한다. 총 가입자 수보다 WAU/MAU 비율이 더 의미 있다.
- 선행 지표(leading)와 후행 지표(lagging)를 균형 있게 포함한다.

### 3. 분기 리뷰 문서

지난 분기 OKR 달성도를 돌아보고 배운 점을 정리하는 문서다.

**구조:**
```
# [회사명] Q[N] OKR 리뷰 — [연도]

## 한줄 요약
이번 분기를 한 문장으로

## OKR 달성도 요약
| Objective | 달성률 | 상태 |
|-----------|--------|------|
(상태: 🟢 달성 / 🟡 부분달성 / 🔴 미달성)

## Objective별 상세 리뷰

### Objective 1: [목표]
**달성률: X%**

| Key Result | 목표 | 실제 | 달성률 | 비고 |
|-----------|------|------|--------|------|

**잘한 점:**
**아쉬운 점:**
**배운 점:**

(각 Objective 반복)

## 전체 회고
- 이번 분기 가장 큰 성과
- 가장 큰 도전/실패
- 다음 분기에 반영할 교훈

## 다음 분기 방향성
리뷰 결과를 바탕으로 한 다음 분기 OKR 방향 제안
```

### 4. 연간 계획 문서

1년 단위의 큰 그림을 그리는 문서다. 분기별 OKR의 상위 프레임이 된다.

**구조:**
```
# [회사명] [연도] 연간 계획

## 비전 & 미션
회사의 장기 비전과 올해의 미션

## 연간 테마
올해를 관통하는 1-3개의 전략적 테마

## 연간 목표 (Annual OKR)
(OKR 설정 문서와 동일한 구조, 연간 스케일)

## 분기별 로드맵
| | Q1 | Q2 | Q3 | Q4 |
|---|----|----|----|----|
| 핵심 목표 | | | | |
| 주요 마일스톤 | | | | |
| 채용 계획 | | | | |
| 예산 배분 | | | | |

## 핵심 가정 & 리스크
이 계획이 전제하는 가정들과 실패 시나리오

## 성공 기준
연말에 "올해는 성공이었다"고 말할 수 있는 조건
```

## 출력 형식

기본 출력은 **PDF** 또는 **프레젠테이션(.pptx)** 이다. 사용자의 용도에 따라 형식을 결정한다:

- **PDF** (기본): 보드/투자자 공유, 사내 배포, 아카이빙에 적합. 깔끔한 레이아웃과 표가 포함된 전문적인 PDF를 생성한다. 관련 pdf 스킬을 반드시 참조하여 생성한다. **반드시 가로(landscape, A4) 방향으로 생성할 것** — OKR 표, KPI 대시보드, 로드맵 등은 가로 방향이어야 정보가 잘 보인다.
- **프레젠테이션 (.pptx)**: OKR 발표, 올핸즈 미팅, 보드 미팅 등 발표 상황에 적합. Keynote에서 열 수 있는 .pptx 형식으로 생성한다. 관련 pptx 스킬을 반드시 참조하여 생성한다. **슬라이드는 표준 와이드스크린(16:9) 가로 방향으로 생성할 것.** 슬라이드 구성:
  - 표지: 회사명, 기간, 문서 유형
  - 요약 슬라이드: 전략 방향 또는 핵심 성과 한눈에
  - Objective별 슬라이드: 각 Objective + Key Results
  - KPI 대시보드 슬라이드: 핵심 지표 표/차트
  - 마일스톤/로드맵 슬라이드
  - 리스크 & 다음 단계
- **마크다운 (.md)**: Notion/Slack에 바로 붙여넣기 위한 용도
- **스프레드시트 (.xlsx)**: KPI 수치 추적이 메인인 경우. 관련 xlsx 스킬 활용.

## 톤 & 스타일

- 간결하고 실행 가능한 언어를 쓴다. 장황한 설명보다 핵심을 짧게.
- 스타트업 맥락에 맞는 용어를 자연스럽게 사용한다 (MRR, CAC, LTV, runway, burn rate 등).
- 투자자/보드 공유용이면 약간 더 포멀하게, 내부용이면 캐주얼하게.
- 한글을 기본으로 하되, 업계에서 영어가 표준인 용어는 영어를 그대로 쓴다 (OKR, KPI, North Star Metric 등).
- 이모지는 상태 표시(🟢🟡🔴)에만 최소한으로 사용한다.
